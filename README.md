# 软件专业课程代码与实验记录

本仓库用于记录软件专业各门课程的实验代码、课程设计与学习笔记。

> ⚠️ **本仓库为 private。**
> 课程作业代码一旦公开，可能被学校查重系统比对，也会成为下一届同学的"答案库"，
> 存在被判定为协助抄袭的风险。**结课一到两年后再考虑转为 public 当作作品集。**

## 目录结构

```
software-coursework/
├─ 数据结构/
│  ├─ lab01-顺序表/
│  ├─ lab02-单链表/
│  └─ README.md          # 该课程的实验清单与完成进度
├─ 程序设计基础/
├─ 计算机导论/
├─ 数据库/
└─ README.md
```

建议：**一门课一个文件夹，每次实验一个子文件夹**。每个实验里放源码 + 一份 `README.md`，
写清题目要求、解题思路、运行方式、踩过的坑。

## 日常工作流

```bash
cd D:\GitHub\software-coursework
git pull                      # 动手前先拉，避免冲突
git add -A
git commit -m "feat(数据结构): 完成 lab02 单链表的插入与删除"
git push
```

**每完成一个小功能就提交一次**，不要攒到期末一次性上传。老师看提交历史能直接看出你的投入曲线；
一个孤零零的"期末大提交"反而显得可疑。

## Commit message 规范

格式：`类型(范围): 简要说明`

| 类型 | 用途 |
|---|---|
| `feat` | 新增功能 / 完成实验 |
| `fix` | 修 bug |
| `docs` | 改文档、写实验报告 |
| `refactor` | 重构，不改变功能 |
| `test` | 添加测试用例 |
| `chore` | 杂项：配置、依赖 |

反例：`update`、`1`、`aaa`、`提交` —— 信息量为零，等于没写。

## 提交前自查清单

- [ ] `git status` 里没有 `.env`、密钥、密码、数据集
- [ ] 没有把 `build/`、`__pycache__`、`*.exe` 等编译产物加进来
- [ ] 单个文件小于 100 MB（GitHub 硬限制）
- [ ] commit message 说清了"做了什么"

## 交作业时注意

老师要仓库地址时：**private 仓库老师是打不开的（会看到 404）**。二选一：

1. Settings → Collaborators 把老师的 GitHub 账号加为协作者；或
2. 确认批改结束后，再把仓库改为 public。
